## 1 系统架构设计

### 1.1 整体架构

系统采用前后端分离的B/S架构：

```
┌─────────────────────────────────────────────────────────────┐
│                        前端层 (Vue.js)                        │
│    LongCatVue - 管理后台 / 求职者端 / 企业端                    │
└──────────────────────┬──────────────────────────────────────┘
                       │ HTTP REST API
                       ▼
┌─────────────────────────────────────────────────────────────┐
│                    后端服务层 (Spring Boot 3.2)                │
│                                                               │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐     │
│  │Controller│→ │ Service  │→ │  Mapper  │→ │ Database │     │
│  │  控制层   │  │  业务层   │  │  数据层   │  │  数据库   │     │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘     │
│       │              │                                        │
│       │        ┌─────┴─────┐                                  │
│       │        │AI Service │→ LongCat API (百炼大模型)          │
│       │        └───────────┘                                  │
│       │        ┌───────────┐                                  │
│       │        │File Service│→ 阿里云OSS / 本地存储             │
│       │        └───────────┘                                  │
│  ┌────┴──────────┐                                           │
│  │ Spring Security│ + JWT Filter                              │
│  └───────────────┘                                           │
└─────────────────────────────────────────────────────────────┘
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
┌──────────────┐ ┌──────────┐ ┌───────────┐
│   MySQL 8    │ │  Redis   │ │ 阿里云OSS  │
│   数据持久化  │ │  缓存层  │ │  文件存储  │
└──────────────┘ └──────────┘ └───────────┘
```

### 1.3 分层架构设计

```
Controller层    → 接收HTTP请求，参数校验，调用Service，返回响应
Service层       → 业务逻辑处理，事务管理，缓存操作
Mapper层        → 数据库CRUD操作（MyBatis Plus BaseMapper）

```

  │  POST /auth/login              │

  │ ──────────────────────────────→│
  │                                │ 1. 验证用户名密码
  │                                │ 2. 检查账户状态
  │                                │ 3. 生成JWT Token
  │  ←──────────────────────────── │ 4. 返回Token + 用户信息
  │  {token, userInfo}             │
  │                                │
  │  GET /api/xxx                  │
  │  Authorization: Bearer <token> │
  │ ──────────────────────────────→│
  │                                │ 1. JwtAuthFilter 拦截

## 4 核心业务设计

### 4.1 智能匹配算法设计

#### 4.1.1 规则匹配引擎

```
输入: 简历(Resume) + 职位(Job)

匹配维度及权重:
├── 技能匹配度 (30%)     → 简历技能 ∩ 职位要求技能 / 职位要求技能
├── 经验匹配度 (25%)     → 简历经验 vs 职位经验要求 区间匹配
├── 学历匹配度 (20%)     → 简历学历 vs 职位学历要求 等级匹配
├── 薪资匹配度 (15%)     → 期望薪资 vs 薪资范围 重叠度
└── 地区匹配度 (10%)     → 期望地区 vs 工作地点 字符匹配

输出: 综合匹配分数(0-100) + 各维度得分
```

#### 4.1.2 AI语义匹配

```
输入: 简历文本摘要 + 职位描述

处理流程:
1. 提取简历核心信息(技能、经验、教育)
2. 拼接匹配提示词
3. 调用 LongCat AI API
4. 解析AI返回的匹配分析

输出: 匹配分数 + 匹配分析文本
```

#### 4.1.3 混合匹配

```
综合分数 = 规则匹配分数 × 0.4 + AI匹配分数 × 0.6
```

## 5 缓存设计

### 5.1 Redis缓存策略

| 缓存内容 | Key格式 | TTL | 说明 |
|---------|---------|-----|------|
| 职位推荐结果 | `match:recommend:jobs:{userId}` | 30分钟 | 按用户缓存推荐职位 |
| 候选人推荐 | `match:recommend:candidates:{jobId}` | 30分钟 | 按职位缓存推荐候选人 |
| 公开统计数据 | `stats:public` | 5分钟 | 登录页展示数据 |

### 5.2 缓存失效策略

- 职位发布/更新/删除时清除相关推荐缓存
- 简历更新时清除相关推荐缓存
- 投递/匹配操作时清除相关缓存
- 提供手动清除缓存接口

## 6 异步处理设计

### 6.1 异步任务

系统通过 `@Async` 注解实现以下异步任务：

| 异步任务 | 触发时机 | 说明 |
|---------|---------|------|
| 匹配计算 | 职位发布/简历更新 | 异步计算简历与职位的匹配分数 |
| 通知发送 | 各业务操作后 | 异步创建通知记录 |
| 技能图谱同步 | 简历创建/更新 | 异步更新技能关联关系 |
| 操作日志记录 | 关键操作 | 异步写入操作日志 |

### 6.2 定时任务

| 任务 | 调度频率 | 说明 |
|------|---------|------|
| 职位订阅匹配 | 定期执行 | 检查新职位与用户订阅条件的匹配 |
